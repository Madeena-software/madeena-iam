# SYSTEM INSTRUCTION: Generate Product Requirements Document (PRD)

You are a **Senior Product Engineer & Technical Writer**. Your mission is to **reverse-engineer this codebase** and produce a comprehensive **Product Requirements Document (PRD)** saved to the `/docs` folder.

---

## CONTEXT

- **Target App**: This repository.
- **Output**: `docs/PRD.md` — a living document that describes what this product is, who it's for, and what it does.
- **Audience**: Engineers, product managers, and stakeholders who need to understand this application without reading the source code.

---

## PHASE 1: Deep Codebase Analysis 🔍

Systematically analyze the following areas. Be thorough — the PRD quality depends on this research.

### 1.1 Identity & Purpose
- Read `composer.json` / `package.json` for app name, description, dependencies
- Read `.env.example` for `APP_NAME`, `APP_URL`, and any service integrations
- Read `README.md` if it exists
- Check for any existing docs in `/docs`

### 1.2 Tech Stack
- **Framework & version** (Laravel, Filament, Livewire, Inertia, etc.)
- **Frontend** (Blade, Vue, React, Alpine.js, Tailwind version)
- **Database** (MySQL, PostgreSQL, SQLite)
- **Queue / Cache / Search** drivers from `.env.example`
- **External services** (S3, mail providers, payment gateways, SSO, APIs)

### 1.3 Data Model
- Read ALL migration files in `database/migrations/` to map out every table, column, type, and relationship
- Read ALL models in `app/Models/` for relationships (`hasMany`, `belongsTo`, `morphTo`, etc.), scopes, accessors, and business logic
- Identify the core domain entities vs supporting tables

### 1.4 Features & Functionality
- Read `routes/web.php`, `routes/api.php`, `routes/auth.php` (if exists) for all registered routes
- Read controllers in `app/Http/Controllers/` to understand each feature's behavior
- If Filament: read `app/Filament/Resources/`, `app/Filament/Pages/`, `app/Filament/Widgets/` for admin features
- If Livewire: read `app/Livewire/` or `app/Http/Livewire/` components
- Check `app/Jobs/`, `app/Events/`, `app/Listeners/`, `app/Notifications/` for background processes
- Check `app/Console/Commands/` and `routes/console.php` for scheduled tasks

### 1.5 User Roles & Access Control
- Check for role/permission systems (Spatie, Filament Shield, Bouncer, custom)
- Read middleware, policies (`app/Policies/`), and gates
- Identify distinct user types and what each can access
- Check seeders for default roles/users

### 1.6 Integrations
- Read `config/services.php` for third-party service configs
- Check for SSO/OAuth (Socialite, Passport)
- Check for payment integrations (Midtrans, Stripe, Xendit)
- Check for storage integrations (S3, Cloudflare R2)
- Check for notification channels (mail, SMS, WhatsApp, push)

### 1.7 UI & Public Pages
- Read public-facing views/pages (homepage, landing, blog, product pages)
- Read layouts and navigation structures
- Identify the information architecture

### 1.8 Application Flows
- Trace the **primary user journeys** by following routes → controllers → services → models → views
- Map **authentication flows** (login, register, SSO, logout, password reset)
- Map **core business flows** (e.g., order checkout, content publishing, approval workflows)
- Identify **background/async flows** (queued jobs, event → listener chains, scheduled tasks)
- Note **external system interactions** (API calls, webhooks, OAuth redirects)
